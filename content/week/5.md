- **Beyond content, we need more document *structure* and *semantic* elements.**

	Almost all the projects need *more* varied/unique HTML elements to work with.

	Pull out some [`<blockquote>`](../topic/html/index.md#blockquote) “pull quotes,” add links and “metadata” around our text, put in some other page “furniture” with a `header` and `footer`! Look for [block elements](../topic/html/index.md#block-elements) for more structure, and appropriate [inline elements](../topic/html/index.md#inline-elements), for style “hooks” to make our text more expressive.

	“Flat” (like `<body><h1>…`) structure will be difficult/impossible to bring to life. Enrich these documents *semantically*, then also *stylistically*. Make it interesting; make it yours!

- **We’re still using elements for their [user-agent styles](../topic/html/index.md#user-agent-styles), not their *meaning*.**

	Pulling in the `reset.css` should have immediately negated this; let’s correct/update our HTML:

	- Don’t use `<br>` for spacing! Unless we’re [writing poetry](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/br), we shouldn’t see these—use `margin` or `padding` instead (as we’ll see today).

	- Don’t use `<h#>` for sizing—headings are for our *semantic* structure, not size. Think about headings like a [document outline](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/Heading_Elements#usage_notes).

		`<h2>` does not mean *smaller* than `<h1>`; it means a new section of content [*nested* under it](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/Heading_Elements#nesting).

	- Likewise, immediately-nested tags:

		```html
		<h3><em><strong>What am I?</strong></em></h3>
		```

		…are usually a bad sign—which one is it *meant* to be? We are probably conflating the style with semantics, again. It probably should be *one* tag and the rest will be in CSS!

	- Only reach for a `div` when no other [semantic elements](https://developer.mozilla.org/en-US/docs/Web/HTML/Element#content_sectioning) are appropriate—we probably shouldn’t see any of these in your code, this project! Unless *absolutely* necessary for some styling trickery.

- **Mind our HTML syntax!**

	Some things to keep in mind as we get more familiar:

	- No spaces around our [tags](../topic/html/index.md#what-are-elements) and [attributes](../topic/html/index.md#attributes):

		```html
		< element attribute = "value" >
		```

		…should be:

		```html
		<element attribute="value">
		```

		The browser *might* interpret things how you want with them, but it can only introduce errors.

	- Line-breaking around text, like this:

		```html
		<p>
			I am some text!
		</p>
		```

		…will [collapse](../topic/html/index.md#inline-whitespace) into an extra space, which can only get us in trouble later. Cinch the tag to the text:

		```html
		<p>I am some text!</p>
		```

	- It’s best/easiest to keep `id` and `class` names lowercase, and they can’t have spaces. You can always [`kebab-them`](https://developer.mozilla.org/en-US/docs/Glossary/Kebab_case)!

- **Build *up* from a comfortable base type size!**

	In the styles we’ve seen so far—the *too-small* type continues! Set our [`:root`/`html`](https://developer.mozilla.org/en-US/docs/Web/CSS/:root) type size larger:

	```css
	:root {
		font-size: 150%; /* Adjust this! */
	}
	```

	This is what all our `rem` values are then based off of—play around with that percentage until our base paragraph feels right/easy/comfortable for readability.
